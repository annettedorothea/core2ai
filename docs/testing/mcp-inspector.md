# MCP Inspector

[← Documentation index](../README.md)

The MCP Inspector is the official debugging and testing tool for the Model Context Protocol ecosystem.

It provides an interactive web interface for inspecting and testing MCP servers generated by `api2ai` and `db2ai`.

Official project:

https://github.com/modelcontextprotocol/inspector

## What is the MCP Inspector?

The MCP Inspector consists of:

- a browser-based user interface
- an MCP proxy process
- transport adapters for HTTP and stdio MCP servers

Typical startup:

```bash
npx @modelcontextprotocol/inspector \
  --transport http \
  --server-url http://127.0.0.1:3849/mcp
```

The Inspector can:

- verify MCP connectivity
- inspect capabilities
- list tools
- inspect schemas
- execute tools interactively
- inspect resources and prompts
- observe notifications and logs

---

## Role in the Testing Strategy

The Inspector complements but does not replace automated tests.

| Layer         | Purpose                                 | Typical Usage   |
| ------------- | --------------------------------------- | --------------- |
| CI tests      | DSL parsing, code generation, snapshots | Every commit    |
| MCP Inspector | Interactive debugging                   | Development     |
| `/test-all`   | End-to-end smoke tests                  | Before releases |

The Inspector is particularly useful for:

- authentication debugging
- session handling
- schema validation
- OAuth flows
- transport debugging

## Using mcp:inspect

Demo workspaces provide:

```bash
npm run mcp:inspect -- <demo-name>
```

The wrapper script:

- loads `.env`
- starts required dependencies
- starts MCP hosts if necessary
- reads configuration from `.cursor/mcp.json`
- launches the MCP Inspector
- cleans up processes on shutdown

## Authentication Modes

### Public HTTP

Examples:

- open-meteo
- spaceflight-news
- plants-oracle

No authentication is required.

---

### Passthrough HTTP

Examples:

- todo
- github
- tmdb
- sakila-mysql
- pagila-postgresql

The wrapper automatically forwards headers from:

```text
.cursor/mcp.json
```

---

### OAuth HTTP

Examples:

- bookings
- cakes
- orders-postgresql

Required values:

- Client ID
- OAuth Server URL
- Scope

The Inspector requires additional redirect URIs:

```text
http://127.0.0.1:6274/oauth/callback
http://127.0.0.1:6274/oauth/callback/debug
```

If custom redirect allowlists are configured, Cursor callbacks must remain present.

---

## OAuth Notes

For quick debugging it is often easier to use a manually generated bearer token.

Example:

```bash
node get-token.mjs alice
```

Then configure:

```text
Authorization: Bearer <token>
```

inside the Inspector.

## Typical Workflow

1. Start the Inspector.
2. Verify the connection.
3. Open the Tools tab.
4. Execute tool calls.
5. Observe notifications and logs.
6. Rebuild and reconnect after code changes.

## Limitations

The MCP Inspector is intended for interactive debugging.

It is not:

- a replacement for `/test-all`
- a CI solution
- a full release validation workflow

OAuth flows are more cumbersome than in Cursor because redirect URIs must be configured manually.

## Troubleshooting

| Problem                                | Likely Cause                          |
| -------------------------------------- | ------------------------------------- |
| Connection refused                     | Host not running                      |
| Missing credential                     | Missing header or OAuth token         |
| invalid_redirect_uri                   | Missing callback in allowlist         |
| Tool fails after successful connection | Upstream API or database unavailable  |
| Session not found                      | Reconnect to create a new MCP session |

## Architecture Context

```text
.api2ai / .db2ai
        ↓
Generator
        ↓
generated tools + MCP hosts
        ↓
MCP Inspector
```

The Inspector is an external tool maintained by the MCP project and is not part of `core2ai`.

The `mcp:inspect` script is merely a convenience wrapper around the Inspector CLI.
