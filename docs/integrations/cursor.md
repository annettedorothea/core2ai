# Cursor Integration

[← Documentation index](../README.md)

Cursor is an AI-native IDE and a common **Layer 3 (AI Runtime)** client for `core2ai` generated MCP tools.

Official Cursor MCP documentation:

https://cursor.com/docs/mcp

---

## Requirements

- Cursor
- Node.js 20+
- Generated tool modules compiled to `.js`

Typical commands:

```bash
npm run build:generated
```

or:

```bash
npm run start
```

For `db2ai` demo workspaces:

```bash
npm run start:all
```

## Configuration File

Cursor reads MCP servers from `mcp.json`.

| Scope   | Path                 | Notes                        |
| ------- | -------------------- | ---------------------------- |
| Project | `.cursor/mcp.json`   | Recommended                  |
| Global  | `~/.cursor/mcp.json` | Available in every workspace |

Top-level key:

```json
{
    "mcpServers": {}
}
```

Project-level configuration overrides global entries with the same server name.

Manage servers via:

```text
Settings → Tools & MCP
```

---

## Supported Transports

| Transport               | Cursor Configuration | core2ai Host                  |
| ----------------------- | -------------------- | ----------------------------- |
| stdio                   | `command` + `args`   | `stdio-mcp-server`            |
| Streamable HTTP         | `url`                | `public-http-mcp-server`      |
| Streamable HTTP         | `url` + `headers`    | `passthrough-http-mcp-server` |
| Streamable HTTP + OAuth | `url` + `auth`       | `oauth-http-mcp-server`       |
| SSE                     | `url`                | not generated by core2ai      |

Cursor automatically detects Streamable HTTP and SSE endpoints.

For new projects, prefer:

- `stdio` for local development
- HTTP for shared hosts and OAuth
- OAuth HTTP for user-specific authentication

See also: [MCP Hosts](../runtime/mcp-hosts.md)

## Choosing a Setup

| Scenario               | Recommended Setup             |
| ---------------------- | ----------------------------- |
| Your own project       | `stdio`                       |
| Demo workspaces        | HTTP                          |
| OAuth APIs             | `oauth-http`                  |
| Shared API keys        | `passthrough-http`            |
| Personal access tokens | `stdio` or `passthrough-http` |

The bundled demo workspaces use HTTP hosts by default.

## stdio Setup

Cursor starts the MCP server as a child process.

Credentials come from environment variables rather than HTTP headers.

### Public API Example

```json
{
    "mcpServers": {
        "open-meteo": {
            "command": "node",
            "args": [
                "${workspaceFolder}/generated/api2ai/cli/stdio-mcp-server.js",
                "${workspaceFolder}/generated/api2ai/tools/open-meteo-tools.js",
                "--base-url-env",
                "OPEN_METEO_BASE_URL"
            ],
            "envFile": "${workspaceFolder}/.env"
        }
    }
}
```

`.env`

```text
OPEN_METEO_BASE_URL=https://api.open-meteo.com
```

---

### Personal Access Token Example

Additional arguments:

```text
--auth-env GITHUB_TOKEN
```

`.env`

```text
GITHUB_BASE_URL=https://api.github.com
GITHUB_TOKEN=ghp_xxxxxxxxxxxx
```

The token is injected into every tool invocation.

Do not commit tokens to `mcp.json`.

---

### db2ai Example

When a generated module exports `connectionEnv`, no `--base-url-env` is required.

Example:

```json
{
    "mcpServers": {
        "pagila": {
            "command": "node",
            "args": [
                "${workspaceFolder}/generated/db2ai/cli/stdio-mcp-server.js",
                "${workspaceFolder}/generated/db2ai/tools/pagila-postgresql-tools.js"
            ],
            "envFile": "${workspaceFolder}/.env"
        }
    }
}
```

## HTTP Setup

Demo workspaces typically use long-running HTTP hosts.

### Public HTTP Example

```json
{
    "mcpServers": {
        "spaceflight-news": {
            "url": "http://127.0.0.1:3849/mcp"
        }
    }
}
```

---

### Passthrough Header Example

```json
{
    "mcpServers": {
        "todo": {
            "url": "http://127.0.0.1:3853/mcp",
            "headers": {
                "x-api-token": "demo-todo-api-key"
            }
        }
    }
}
```

Header names must match the MCP host configuration.

---

### Host-side Credentials

For services such as GitHub or TMDB:

```json
{
    "mcpServers": {
        "github": {
            "url": "http://127.0.0.1:3854/mcp"
        }
    }
}
```

Credentials live in:

```text
.env
```

and are injected by the host via:

```text
--auth-env
```

## OAuth Setup

Example:

```json
{
    "mcpServers": {
        "bookings": {
            "url": "http://127.0.0.1:3872/mcp",
            "auth": {
                "CLIENT_ID": "mcp-demo-local"
            }
        }
    }
}
```

First use:

1. Start the MCP host.
2. Open:

```text
Settings → Tools & MCP
```

3. Click:

```text
Connect / Sign-in
```

4. Complete the browser OAuth flow.

Cursor stores the access token automatically.

Cursor callback URI:

```text
cursor://anysphere.cursor-mcp/oauth/callback
```

This URI must be included in:

```text
OAUTH_IDP_REDIRECT_URIS
```

## Demo Workspace Quick Start

### api2ai

1. Install the VSIX.
2. Run:

```text
api2ai: Create demo workspace
```

3. Open the generated workspace.
4. Start the demos:

```bash
npm run start
```

5. Enable MCP servers in:

```text
Settings → Tools & MCP
```

```text
api2ai What will the weather be like tomorrow in Berlin?
```

```bash
npm run start:all
```

Example prompt:

```text
db2ai List films in Sakila with rating PG.
```

## Using Generated Tools in Chat

Prefixing prompts with `api2ai` or `db2ai` helps Cursor focus on generated MCP tools and avoid unrelated built-in tools.

Examples:

```text
api2ai List my GitHub repositories.
```

```text
db2ai Show the ten most rented films.
```

This approach has proven especially useful in larger workspaces with many available tools.

## Secrets and mcp.json

| Pattern               | Secret Location    | mcp.json         |
| --------------------- | ------------------ | ---------------- |
| stdio + `--auth-env`  | `.env`             | no secrets       |
| HTTP host credentials | `.env`             | URL only         |
| Passthrough           | headers            | header values    |
| OAuth                 | Cursor token store | `CLIENT_ID` only |

Do not commit:

- API keys
- Personal access tokens
- Database passwords

## Regenerate and Restart

After changing DSL files:

```bash
npm run build:generated
```

Restart the MCP host afterwards.

If code generation templates changed:

1. Rebuild `core2ai`
2. Rebuild the consumer project
3. Regenerate tool code
4. Restart Cursor MCP servers

## Troubleshooting

| Problem               | Check                                     |
| --------------------- | ----------------------------------------- |
| No tools available    | Generated `.js` files exist? MCP enabled? |
| Connection refused    | MCP host running? Port correct?           |
| 401 on GitHub or TMDB | Token configured in `.env`?               |
| OAuth login fails     | IdP running? Redirect URI configured?     |
| Stale tools           | Restart the MCP server                    |
| Agent ignores tools   | Agent mode enabled? Server active?        |
