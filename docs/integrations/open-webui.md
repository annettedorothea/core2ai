## What is Open WebUI?

Open WebUI is a self-hosted chat interface for large language models.

Within the `core2ai` architecture, Open WebUI belongs to **Layer 3 (AI Runtime)**, where agents consume MCP tools generated by `api2ai` and `db2ai`.

Official Open WebUI MCP documentation:

https://docs.openwebui.com/features/extensibility/mcp/

---

## Requirements

- Open WebUI **0.6.31** or newer
- An HTTP MCP host using **Streamable HTTP**
- A running `core2ai` generated MCP host

Open WebUI does not support stdio-based MCP servers directly.

---

## Supported MCP Hosts

| Host Type                     | Transport                   | Open WebUI             |
| ----------------------------- | --------------------------- | ---------------------- |
| `public-http-mcp-server`      | Streamable HTTP             | ✅ Supported           |
| `passthrough-http-mcp-server` | Streamable HTTP             | ✅ Supported           |
| `oauth-http-mcp-server`       | Streamable HTTP + OAuth 2.1 | ✅ Supported           |
| `stdio-mcp-server`            | stdio                       | ❌ Requires MCPO proxy |

Generated HTTP hosts expose MCP endpoints under `/mcp`.

Example:

```text
http://127.0.0.1:3849/mcp
```

Always include the protocol (`http://`) when configuring Open WebUI.

---

## Recommended Host Types

| Scenario                 | Recommended Host              |
| ------------------------ | ----------------------------- |
| Cursor development       | `stdio-mcp-server`            |
| Open WebUI integration   | `public-http-mcp-server`      |
| Shared team environments | `passthrough-http-mcp-server` |
| OAuth protected APIs     | `oauth-http-mcp-server`       |

For Open WebUI deployments, HTTP hosts are generally preferred over stdio hosts.

## Adding an MCP Server

1. Log in as an administrator.
2. Open **Admin Settings → External Tools**.
3. Click **Add Server**.
4. Select:

```text
Type: MCP (Streamable HTTP)
```

Do **not** choose OpenAPI.

5. Enter the MCP endpoint URL:

```text
http://127.0.0.1:3849/mcp
```

6. Configure authentication if required.
7. Click **Verify Connection**.
8. Save the configuration.

`Verify Connection` works without an LLM connection and is useful for debugging transport or authentication problems.

Only administrators can register MCP servers in Open WebUI.

## Authentication Profiles

### Public Hosts

`public-http-mcp-server`

No authentication configuration is required in Open WebUI.

Typical use cases:

- public APIs
- local development
- demos

---

### Passthrough Hosts

`passthrough-http-mcp-server`

The upstream credential is provided by the MCP host via `--auth-env`.

Open WebUI usually sends a custom header:

```json
{
    "x-api-token": "demo"
}
```

Header names and values are configured using project environment variables such as:

- `MCP_AUTH_HEADER`
- `MCP_AUTH_EXPECTED`
- `TODO_API_KEY`

---

### OAuth Hosts

`oauth-http-mcp-server`

Configure Open WebUI using:

- Client ID
- Client Secret
- OAuth Server URL

The OAuth server URL corresponds to the IdP base URL configured in your project.

Redirect allowlists must contain Open WebUI callback URLs:

```text
http://localhost:3000/oauth/clients/mcp:*
http://127.0.0.1:3000/oauth/clients/mcp:*
```

The following variable controls allowed redirects:

```text
OAUTH_IDP_REDIRECT_URIS
```

Restart the IdP after changing redirect settings.

## Activating Tools in Chats

After a successful connection:

1. Open a chat.
2. Click the **Integrations** button (diamond icon).
3. Enable the MCP tools for this conversation.

If the tool list is empty, reload the page.

---

## Function Calling

Open WebUI only invokes MCP tools reliably when the selected model supports native function calling.

Recommended configuration:

```text
Function Calling = Native
```

Examples include:

- Groq models
- OpenAI models with tool support
- Ollama models with native function calling

## Using the Demo Workspaces

The demo workspaces provide helper scripts for Open WebUI integration.

### api2ai

```bash
cd packages/extension/demos

npm run start
npm run open-webui
```

Or:

```bash
npm run start:open-webui
```

---

### db2ai

```bash
cd packages/extension/demos

npm run start:all
npm run open-webui
```

Or:

```bash
npm run start:open-webui
```

The startup scripts print:

- MCP URLs
- Authentication mode
- Required headers
- OAuth configuration values

Open WebUI itself is not part of the repositories and must be installed separately.

## Open WebUI Installation

Install once using:

```bash
pipx install open-webui
```

Alternatively:

```bash
python3 -m pip install --user open-webui
```

If `open-webui` is not available on your `PATH`, configure:

```text
OPEN_WEBUI_COMMAND
```

Default locations used by the demo scripts:

```text
~/.open-webui-data
~/.open-webui-secret
```

## Using Open WebUI With Your Own Projects

1. Generate an HTTP MCP host.
2. Start the MCP host.
3. Verify that the endpoint is reachable:

```text
http://127.0.0.1:<port>/mcp
```

4. Register the endpoint in Open WebUI.
5. Configure authentication if required.

For OAuth hosts, remember to add Open WebUI callback URLs to your redirect allowlist.

---

## Using stdio Hosts

Open WebUI does not support stdio MCP servers directly.

Possible alternatives:

- Use MCPO as an MCP → OpenAPI proxy.
- Use one of the generated HTTP MCP hosts.

For Open WebUI deployments, HTTP hosts are generally recommended.

---

## Troubleshooting

| Problem                          | Check                                                               |
| -------------------------------- | ------------------------------------------------------------------- |
| Verify Connection fails          | Is the MCP host running? Does the URL contain `http://` and `/mcp`? |
| Tools do not appear              | Reload Open WebUI and re-open the chat                              |
| The model never calls tools      | Ensure `Function Calling = Native`                                  |
| OAuth redirect errors            | Verify `OAUTH_IDP_REDIRECT_URIS`                                    |
| Passthrough authentication fails | Verify custom headers configured in Open WebUI                      |
